### 前提として読むべきドキュメント

同梱の以下を先に読んでください。仕様の正は常にこれらのドキュメントです。

- `04_データベース設計書.md` — DDL・RLS・RPC関数の完全な実装。**SQLはこのファイルの内容をそのまま使うこと**
- `05_API仕様書.md` — クライアントからの呼び出し方とレスポンス形式
- `06_画面仕様書.md` — 全画面のレイアウト・挙動・文言
- `07_印刷仕様書.md` — CloudPRNT の Edge Function 実装

### 技術スタック（変更しないこと）

| 領域 | 指定 |
|---|---|
| フロントエンド | React 18 + TypeScript + Vite |
| スタイル | Tailwind CSS v4 |
| ルーティング | react-router-dom v6 |
| 状態管理 | Zustand（グローバルは最小限に。多くはローカルstateで足りる） |
| バックエンド | Supabase（PostgreSQL / Auth / Realtime / Edge Functions） |
| QRコード生成 | `qrcode.react` |
| グラフ | Recharts（統計画面のみ） |
| ホスティング | Cloudflare Pages（静的SPAとしてビルド） |

**使わないでほしいもの**：Next.js、状態管理の重量級ライブラリ、UIコンポーネントライブラリ（MUI等）、i18nライブラリ。
このシステムは画面数が10で、独自レイアウトが多いため、素のTailwindで書いたほうが速く仕上がります。

### 実装の順序（この順で作り、各フェーズの終わりに必ず動作確認すること）

**Phase 1 — 基盤とDB**
1. Vite + React + TS + Tailwind のプロジェクトを作る
2. `supabase/migrations/` に `04_データベース設計書.md` のSQLを分割配置し、適用する
3. `src/lib/supabase.ts` と `src/lib/types.ts`（DBの型定義）を書く
4. **確認**: SQL Editor で `select public.issue_ticket(...)` を実行し、`tickets` に行ができ `queue_states` が更新されること

**Phase 2 — 発券キオスク**
1. `/k/:tenantSlug` を実装。`get_public_queues` でキュー一覧を取得
2. `queue_states` のRealtime購読で待ち組数をライブ更新
3. ステップ2（人数・部屋番号・席希望）を実装。**部屋番号は自作テンキーで入力し、OSキーボードを出さないこと**
4. `issue_ticket` を `crypto.randomUUID()` のnonce付きで呼ぶ
5. ステップ3で番号とQR（`qrcode.react`）を巨大表示し、15秒で自動復帰
6. オフライン検知（`navigator.onLine` + 30秒ごとのRPC疎通確認）でオーバーレイ表示
7. **確認**: iPadのSafariで3タップ以内に発券でき、連打しても1枚しか出ないこと

**Phase 3 — スタッフ画面**
1. `/login`（Supabase Auth のメール+パスワード）と `RequireAuth`
2. `/staff` ダッシュボード
3. `/staff/q/:queueId` 待ち行列管理。左に「次を呼ぶ」、右に呼出中と待機列
4. `tickets` のRealtime購読で他端末の操作を即座に反映
5. 呼出・ご案内・完了・不在・再呼出・不在リスト・代理発券を実装
6. 経過時間は1秒ごとに再計算して表示（`setInterval` 1本で全行をまとめて更新すること）
7. **確認**: 2つのブラウザで同時に「次を呼ぶ」を押し、**異なる番号**が呼ばれること

**Phase 4 — サイネージ**
1. `/s/:tenantSlug`。初回に「画面をタップして開始」を全面表示し、AudioContextを解放する
2. `queue_states` を購読し、`called_seq` の増加で点滅＋チャイム＋音声読み上げ
3. 読み上げは `06_画面仕様書.md` 4.1節の `speak()` をそのまま使う（数字は1桁ずつ読ませる）
4. 複数呼出が同時に来たらキューに積み、4秒間隔で順に処理する
5. 90秒間 `updated_at` が更新されなければ `location.reload()`
6. **確認**: 呼び出しから1秒以内に番号が出て、日本語と英語で読み上げられること

**Phase 5 — 印刷**
1. `supabase/functions/cloudprnt/index.ts` を `07_印刷仕様書.md` 5章のコードで実装
2. `npx supabase functions deploy cloudprnt --no-verify-jwt` でデプロイ（**フラグ必須**）
3. `/admin/printers` を実装。設定用URLの表示とコピー、テスト印刷、状態表示
4. プリンタ本体を `07_印刷仕様書.md` 7章の手順で設定
5. **確認**: 発券から10秒以内に紙が出て、QRがiPhoneの標準カメラで読めること

**Phase 6 — ゲストステータス**
1. `/t/:token` を実装。`get_ticket_status` で取得し、`queue_states` の変化で再取得
2. 状態ごとに画面を出し分ける（`06_画面仕様書.md` 3章）
3. `called` のとき全面赤の明滅＋音＋振動。30秒で明滅停止
4. `navigator.wakeLock` で画面消灯を抑止
5. 5分バックグラウンドで購読解除、復帰時に再購読＋再取得
6. **確認**: 券のQRを読んで順位が見え、呼ばれると赤く光ること

**Phase 7 — 管理・多言語・統計**
1. `/admin/queues`（券面ライブプレビュー付き）、`/admin/staff`
2. `src/lib/i18n.ts` に4言語の辞書を作り、ゲスト向け3画面を完全対応させる
3. `/staff/analytics`（Recharts）
4. `send-push` と `daily-maintenance` の Edge Function
5. `.github/workflows/backup.yml`

### 実装上の必須ルール

1. **`tickets` テーブルへの書き込みは、必ずRPC経由で行うこと。** クライアントから `.from('tickets').insert()` や `.update()` を直接呼んではいけません。採番の一貫性と監査ログの記録がRPC内にあるためです。読み取り（`.select()`）はスタッフ画面のみ直接で構いません。

2. **`issue_ticket` は必ず `p_client_nonce` を渡すこと。** リトライ時は同じ値を使い、新しく生成しないでください。二重発券防止の要です。

3. **Realtimeのペイロードを信用して画面を組み立てないこと。** ゲスト画面では `queue_states` の変化を「再取得のきっかけ」としてのみ使い、表示する値は必ず `get_ticket_status` の結果を使ってください。個人情報をRealtimeに流さないための設計です。

4. **Edge Function を業務ロジックに使わないこと。** 無料枠の呼び出し回数が最も逼迫するリソースです。プリンタ連携とPush送信以外は、すべてDBのRPCで処理してください。

5. **`--no-verify-jwt` を付けずに `cloudprnt` をデプロイしないこと。** プリンタはAuthorizationヘッダを送れないため、付け忘れると印刷が一切動きません。

6. **音声再生の前に必ずユーザー操作を挟むこと。** iOSは自動再生を禁止しています。サイネージは初回タップで、ゲスト画面は最初の任意のタップで、無音の `AudioContext` を再生してアンロックしてください。

7. **タイマーは1画面に1本にまとめること。** 待機列の経過時間表示で、行ごとに `setInterval` を張るとiPadが重くなります。1本の `setInterval` で `now` を更新し、各行はそれを参照してください。

8. **エラー時にゲストを困らせないこと。** 印刷が失敗しても発券は成功させ、画面に番号とQRを出してください。ネットワークが切れたら「スタッフにお声がけください」と明示してください。無言で固まるのが最悪です。

9. **破壊的操作には確認ダイアログを出すこと。** 「不在」「取消」は誤タップで業務が止まります。

10. **console.log を残さないこと。** 本番ビルドで消えるようにするか、そもそも書かないでください。

## 補足：フェーズ分割して依頼する場合

一度に全部を依頼すると品質が落ちるため、**Phaseごとに区切って依頼する**ことを推奨します。その場合、各回の冒頭に以下を付けてください。

```
前回までに Phase N まで完了しています。既存のコードを尊重し、
今回は Phase N+1 のみを実装してください。
既存ファイルを大きく書き換える必要がある場合は、
実装前に理由を説明してください。
```

## 補足：レビュー時に確認すべき点

AIが実装したコードをレビューする際、以下を重点的に見てください。経験上、ここが崩れやすい箇所です。

| 確認箇所 | 見るポイント |
|---|---|
| 発券処理 | `.from('tickets').insert()` を直接呼んでいないか。nonceがリトライ時に再生成されていないか |
| Realtime | ゲスト画面で `payload.new` の中身をそのまま表示していないか（個人情報が漏れる） |
| タイマー | 待機列の行ごとに `setInterval` を張っていないか |
| 購読解除 | `useEffect` のクリーンアップで `channel.unsubscribe()` を呼んでいるか |
| 音声 | `AudioContext` のアンロック処理が入っているか |
| Edge Function | `--no-verify-jwt` でデプロイされているか。ポーリング間隔の動的制御が効いているか |
| 型 | `any` が散らばっていないか。DBの型定義が `supabase gen types` から生成されているか |
