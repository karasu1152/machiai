# MACHIAI 印刷仕様書（CloudPRNT）

版数: 1.0

このシステムで最も特殊な部分。**ここを最初に理解すれば、残りは普通のWebアプリです。**

---

## 1. なぜこの方式なのか

### 1.1 素直にやろうとすると詰まる

iPadのSafariから、LAN内のレシートプリンタに自動印刷したい。普通に考えると次の2つが浮かぶ。

| 案 | なぜ駄目か |
|---|---|
| ブラウザの印刷ダイアログ（AirPrint）を使う | 印刷のたびにユーザーが「プリント」をタップする必要があり、**無人発券にならない**。用紙サイズの調整もダイアログ任せになる |
| JavaScriptからプリンタのIPを直接叩く<br>（ePOS-Print / WebPRNT） | サイトがHTTPSなのに対しプリンタはHTTP。ブラウザが **Mixed Content** としてブロックする。プリンタ側にHTTPSを入れても自己署名証明書のため信頼されない |

### 1.2 発想を逆にする

**プリンタのほうからサーバーに「仕事ありますか？」と聞きに行かせる。**

これがStar Micronicsの **CloudPRNT** プロトコル。プリンタが定期的にサーバーへHTTP POSTを送り、印刷ジョブがあれば受け取って印刷する。

```
     ✗ 従来の発想                    ✓ CloudPRNT
  ブラウザ ──HTTP──▶ プリンタ      サーバー ◀──HTTPS── プリンタ
        （ブロックされる）                （プリンタから接続）
```

これで得られるもの：

- **iPad側の設定がゼロになる**。ブラウザは発券APIを呼ぶだけで、印刷のことを一切知らない
- **Mixed Content の問題が消える**。通信はプリンタ→サーバーの一方向で、すべてHTTPS
- **プリンタが別の建物にあっても動く**。LANの構成に依存しない
- **iPadが壊れても、他の端末から発券すれば同じプリンタから出る**

代償は「ポーリング間隔ぶんの遅延（最大10秒）」だけ。整理券の発行には十分許容できる。

## 2. 対応機種

| 機種 | CloudPRNT | 判定 |
|---|---|---|
| **Star mC-Print3 `MCP31CBI`** | ○（HTTP / MQTT） | ✅ **推奨。** USB-C + Bluetooth + Ethernet |
| **Star mC-Print3 `MCP31CI`** | ○（HTTP / MQTT） | ✅ 可。Bluetooth不要ならこちら |
| Star mC-Print3 `MCP31LB` / `MCP31L` | ✕ | ❌ **不可** |
| Star mC-Print2 / TSP100IV | ○ | ⭕ 動作するが3インチ幅の mC-Print3 を推奨 |
| Epson TM-m30III | △（サーバーダイレクトプリント） | ⭕ 同等の方式あり。ただし本書のコードはStar向け |

**購入時の注意：型番の末尾を必ず確認すること。** `MCP31LB`（CloudPRNT非対応）と `MCP31CBI`（対応）は見た目がほぼ同じ。

### 実売価格の目安

`MCP31LB WT JP` が税込 約63,000円（モノタロウ価格）。`MCP31CBI` も同程度の価格帯。
中古やレンタル（Star Direct で月額レンタルあり）も選択肢になる。

## 3. プロトコル

CloudPRNTは3つのHTTPメソッドで完結する。すべて同一のURLに対して行われる。

### 3.1 全体の流れ

```
プリンタ                                        サーバー(Edge Function)
   │                                                    │
   │ ① POST  /cloudprnt?token=xxx                       │
   │    {"status":"...","printerMAC":"...", ... }       │
   ├───────────────────────────────────────────────────▶│
   │                                                    │ printers を更新
   │                                                    │ print_jobs を検索
   │ ← {"jobReady":true,                                │
   │     "mediaTypes":["text/vnd.star.markup"],         │
   │     "jobToken":"<job-uuid>",                       │
   │     "deleteMethod":"DELETE"}                       │
   │◀───────────────────────────────────────────────────┤
   │                                                    │
   │ ② GET   /cloudprnt?token=xxx&uid=<job-uuid>        │
   │         &mac=...&type=text/vnd.star.markup         │
   ├───────────────────────────────────────────────────▶│
   │ ← Content-Type: text/vnd.star.markup               │
   │   [align: center] ...  （券面本文）                  │
   │◀───────────────────────────────────────────────────┤
   │                                                    │
   │  ★ここで実際に印刷される★                            │
   │                                                    │
   │ ③ DELETE /cloudprnt?token=xxx&uid=<job-uuid>&code=OK│
   ├───────────────────────────────────────────────────▶│
   │                                                    │ status='confirmed'
   │ ← 200 OK                                           │
   │◀───────────────────────────────────────────────────┤
```

### 3.2 ① POST（ポーリング）

プリンタが `poll_interval_seconds` ごとに送信する。

**リクエストボディ（プリンタ→サーバー）**

```json
{
  "status": "200 OK",
  "printerMAC": "00:11:62:4a:1b:2c",
  "statusCode": "20 00 00 00 00 00",
  "printingInProgress": false,
  "clientAction": [
    { "request": "GetPollInterval", "options": "" }
  ]
}
```

**レスポンス（サーバー→プリンタ）— 印刷ジョブがある場合**

```json
{
  "jobReady": true,
  "mediaTypes": ["text/vnd.star.markup"],
  "jobToken": "9f8c1b2e-3d4a-4f5b-8c6d-7e8f9a0b1c2d",
  "deleteMethod": "DELETE",
  "clientAction": [
    { "request": "PollInterval", "result": "10000" }
  ]
}
```

**レスポンス — ジョブがない場合**

```json
{ "jobReady": false, "clientAction": [{ "request": "PollInterval", "result": "10000" }] }
```

> `clientAction` の `PollInterval` でポーリング間隔をサーバー側から動的に指示できる。
> **これが無料枠を守る鍵**（後述の第6章）。

### 3.3 ② GET（ジョブ本文の取得）

```
GET /cloudprnt?token=xxx&uid=9f8c1b2e-...&mac=00:11:62:4a:1b:2c&type=text/vnd.star.markup
```

レスポンスヘッダに正しい `Content-Type` を付けて、券面のマークアップを本文として返す。

```
HTTP/1.1 200 OK
Content-Type: text/vnd.star.markup

[align: center]
[magnify: width 2; height 2]グランドメルキュール浜名湖[plain]
...
```

### 3.4 ③ DELETE（完了確認）

```
DELETE /cloudprnt?token=xxx&uid=9f8c1b2e-...&code=OK
```

`code=OK` なら印刷成功。それ以外（`code=ERROR` など）は失敗として記録し、再送対象にする。

## 4. 券面マークアップ（Star Document Markup）

`text/vnd.star.markup` は、Starプリンタが解釈するテキストベースの記法。バイナリのESC/POSコマンドを書かずに済むため、SQLからでも簡単に生成できる。

### 4.1 使用するタグ

| タグ | 用途 | 例 |
|---|---|---|
| `[align: center\|left\|right]` | 揃え位置 | `[align: center]` |
| `[magnify: width N; height N]` | 文字の拡大（1〜6） | `[magnify: width 4; height 4]` |
| `[plain]` | 装飾をすべて解除 | `[plain]` |
| `[bold]` / `[plain]` | 太字 | `[bold]C-012[plain]` |
| `[feed: N]` | N行送り | `[feed: 2]` |
| `[cut: partial; feed]` | 用紙を送ってパーシャルカット | `[cut: partial; feed]` |
| `[barcode: type qr; data "..."; cell N; error-correction level]` | QRコード | 下記参照 |
| `[buzzer]` | ブザーを鳴らす | 発券時の注意喚起に使える |
| `[logo: ...]` | プリンタに保存したロゴを印字 | 任意 |

### 4.2 QRコードの記法

```
[barcode: type qr; data "https://machiai.pages.dev/t/aB3xK9mZ7pQ2rT5vW8yC1e"; cell 6; error-correction medium]
```

| パラメータ | 意味 | 本システムの設定 |
|---|---|---|
| `type qr` | QRコードを指定 | 固定 |
| `data` | エンコードする文字列 | ステータス画面のURL |
| `cell` | セルサイズ（1〜8ドット） | **6**（80mm紙で約2.5cm角になり、スマホで確実に読める） |
| `error-correction` | 誤り訂正レベル | **medium**（15%。感熱紙の擦れに耐える） |

> `cell 3`（既定値）だと小さすぎて、暗いロビーでは読み取りに失敗しやすい。**必ず6を指定すること。**
> 58mm紙を使う場合は `cell 4` に下げる（用紙幅を超えると印字されない）。

### 4.3 完成する券面（80mm紙・日本語）

```
[align: center]
[magnify: width 2; height 2]グランドメルキュール浜名湖[plain]
[feed: 1]
レストラン（朝食）
[feed: 1]
[magnify: width 4; height 4]R-024[plain]
[feed: 1]
[align: left]
お待ちの組数 : 5
目安待ち時間 : 20分
ご人数 : 2
お部屋番号 : 805
[feed: 1]
[align: center]
[barcode: type qr; data "https://machiai.pages.dev/t/aB3xK9mZ7pQ2rT5vW8yC1e"; cell 6; error-correction medium]
[feed: 1]
QRコードでお呼び出し状況を確認できます。
画面を開いたままお待ちください。
[feed: 1]
2026/08/26 07:42
[feed: 3]

```

### 4.4 用紙幅ごとの調整

| 用紙幅 | 1行の文字数（フォントA） | QRの `cell` | 番号の `magnify` |

| 80mm | 48桁（全角24文字） | 6 | 4 |
| 58mm | 32桁（全角16文字） | 4 | 3 |

`printers.paper_width` と `printers.chars_per_line` を見て切り替える。

## 5. Edge Function 実装

`supabase/functions/cloudprnt/index.ts`

```typescript
// ============================================================
// CloudPRNT エンドポイント
//   デプロイ: npx supabase functions deploy cloudprnt --no-verify-jwt
//   ⚠️ --no-verify-jwt は必須。プリンタはAuthorizationヘッダを送れない。
// ============================================================
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';

const supabase = createClient(
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!,   // RLSを迂回するため service_role を使う
);

// MACアドレスの表記ゆれを吸収（コロン有無・大文字小文字）
const normalizeMac = (m: string | null) =>
  (m ?? '').replace(/[^0-9a-fA-F]/g, '').toUpperCase();

// statusCode から人が読めるエラー名を得る
function decodeStatus(code: string): { hasError: boolean; label: string | null } {
  const bytes = code.trim().split(/\s+/).map((h) => parseInt(h, 16));
  if (bytes.length < 3 || bytes.some(Number.isNaN)) return { hasError: false, label: null };
  // ASB(Automatic Status Back) の代表的なビット
  if (bytes[2] & 0x08) return { hasError: true, label: '用紙切れ' };
  if (bytes[2] & 0x04) return { hasError: true, label: '用紙残量わずか' };
  if (bytes[1] & 0x20) return { hasError: true, label: 'カバーオープン' };
  if (bytes[1] & 0x08) return { hasError: true, label: 'オフライン' };
  if (bytes[1] & 0x40) return { hasError: true, label: 'メカニカルエラー' };
  return { hasError: false, label: null };
}

// 営業時間に応じてポーリング間隔をミリ秒で返す（無料枠の節約）
function pollIntervalMs(now: Date, base: number): number {
  const jstHour = (now.getUTCHours() + 9) % 24;
  // 6:00-11:00 と 14:00-21:00 は稼働ピーク → 通常間隔
  const busy = (jstHour >= 6 && jstHour < 11) || (jstHour >= 14 && jstHour < 21);
  return busy ? base * 1000 : 60 * 1000;   // 閑散時は60秒に延ばす
}

Deno.serve(async (req) => {
  const url = new URL(req.url);
  const token = url.searchParams.get('token') ?? '';

  // ---- プリンタの認証 ----
  const { data: printer } = await supabase
    .from('printers')
    .select('*')
    .eq('device_token', token)
    .eq('is_active', true)
    .maybeSingle();

  if (!printer) return new Response('Unauthorized', { status: 401 });

  // ============================================================
  // ① POST : ポーリング
  // ============================================================
  if (req.method === 'POST') {
    let body: Record<string, unknown> = {};
    try { body = await req.json(); } catch { /* 空ボディも許容 */ }

    const mac = normalizeMac((body.printerMAC as string) ?? null);
    // 登録済みMACと一致しなければ拒否（トークン漏洩時の二重防御）
    if (mac && normalizeMac(printer.mac_address) !== mac) {
      return new Response('Forbidden', { status: 403 });
    }

    const statusCode = (body.statusCode as string) ?? '';
    const { hasError, label } = decodeStatus(statusCode);

    await supabase.from('printers').update({
      last_seen_at: new Date().toISOString(),
      status_code: statusCode,
      is_online: true,
      has_error: hasError,
      error_label: label,
    }).eq('id', printer.id);

    const interval = pollIntervalMs(new Date(), printer.poll_interval_seconds);

    // 印刷中は新しいジョブを渡さない
    if (body.printingInProgress === true) {
      return json({ jobReady: false, clientAction: [pollAction(interval)] });
    }

    // 最も古い未処理ジョブを1件取る
    const { data: job } = await supabase
      .from('print_jobs')
      .select('id, media_type')
      .eq('printer_id', printer.id)
      .in('status', ['queued'])
      .gt('expires_at', new Date().toISOString())
      .order('created_at', { ascending: true })
      .limit(1)
      .maybeSingle();

    if (!job) {
      return json({ jobReady: false, clientAction: [pollAction(interval)] });
    }

    return json({
      jobReady: true,
      mediaTypes: [job.media_type],
      jobToken: job.id,
      deleteMethod: 'DELETE',
      clientAction: [pollAction(interval)],
    });
  }

  // ============================================================
  // ② GET : ジョブ本文の取得
  // ============================================================
  if (req.method === 'GET') {
    const uid = url.searchParams.get('uid');
    if (!uid) return new Response('Bad Request', { status: 400 });

    const { data: job } = await supabase
      .from('print_jobs')
      .select('id, payload, media_type, attempts')
      .eq('id', uid)
      .eq('printer_id', printer.id)
      .maybeSingle();

    if (!job) return new Response('Not Found', { status: 404 });

    await supabase.from('print_jobs').update({
      status: 'delivered',
      delivered_at: new Date().toISOString(),
      attempts: (job.attempts ?? 0) + 1,
    }).eq('id', job.id);

    return new Response(job.payload, {
      status: 200,
      headers: { 'Content-Type': job.media_type },
    });
  }

  // ============================================================
  // ③ DELETE : 印刷完了の確認
  // ============================================================
  if (req.method === 'DELETE') {
    const uid = url.searchParams.get('uid');
    const code = url.searchParams.get('code') ?? '';
    if (!uid) return new Response('Bad Request', { status: 400 });

    const ok = code.toUpperCase() === 'OK';

    const { data: job } = await supabase
      .from('print_jobs')
      .update({
        status: ok ? 'confirmed' : 'failed',
        confirmed_at: new Date().toISOString(),
        error_message: ok ? null : `printer returned code=${code}`,
      })
      .eq('id', uid)
      .eq('printer_id', printer.id)
      .select('ticket_id')
      .maybeSingle();

    if (job?.ticket_id) {
      await supabase.from('tickets')
        .update({ print_status: ok ? 'printed' : 'failed' })
        .eq('id', job.ticket_id);
    }

    return new Response('OK', { status: 200 });
  }

  return new Response('Method Not Allowed', { status: 405 });
});

// ---- ヘルパー ----
function json(obj: unknown) {
  return new Response(JSON.stringify(obj), {
    status: 200,
    headers: { 'Content-Type': 'application/json' },
  });
}
function pollAction(ms: number) {
  return { request: 'PollInterval', result: String(ms) };
}
```

## 6. ポーリング間隔の最適化（無料枠を守る）

Supabase無料プランの Edge Function 呼び出しは **月50万回**。ポーリングは呼び出し回数を確実に消費するため、設計時に必ず試算すること。

| ポーリング間隔 | 1日の呼び出し | 月間 | 判定 |
|---|---|---|---|
| 5秒・24時間 | 17,280回 | 518,400回 | ❌ 超過 |
| 10秒・24時間 | 8,640回 | 259,200回 | ⚠️ 52%消費。GETとDELETEを足すと危険 |
| **10秒（ピーク時のみ）+ 60秒（閑散時）** | **約5,000回** | **約150,000回** | ✅ **推奨。30%消費** |
| 15秒・24時間 | 5,760回 | 172,800回 | ⭕ 可 |

上記コードの `pollIntervalMs()` が、朝食時間帯（6:00-11:00）とチェックイン時間帯（14:00-21:00）だけ10秒に、それ以外を60秒にしている。

> **プリンタ2台目を追加する場合は、この試算をやり直すこと。** 呼び出し回数は台数に比例する。

## 7. プリンタ本体の設定手順

プリンタの設定は Web UI から行う。

1. プリンタを**有線LAN**でルーターに接続し、電源を入れる
2. FEEDボタンを押しながら電源を入れ、**セルフプリント**でIPアドレスを確認する
3. PCのブラウザで `http://<プリンタのIP>` を開く（初期ID/PW: `root` / `public`）
4. 左メニュー **CloudPRNT** を開き、以下を設定する

| 項目 | 設定値 |
|---|---|
| CloudPRNT | **Enable** |
| Server URL | `https://<project-ref>.supabase.co/functions/v1/cloudprnt?token=<device_token>` |
| Poll Interval | `10` （秒。サーバー側から動的に上書きされる） |
| Communication Protocol | `HTTP` |
| Encryption | `Enable`（HTTPS） |

5. **Save → Restart Device** で再起動
6. 管理画面の「プリンタ設定」を開き、`last_seen_at` が更新されていることを確認する
7. 「テスト印刷」ボタンを押し、紙が出れば完了

`device_token` は `printers` テーブルの値。管理画面に表示する。

### MACアドレスの登録

セルフプリントに印字されるMACアドレス（例 `00:11:62:4A:1B:2C`）を、管理画面から `printers.mac_address` に登録する。コロンの有無・大文字小文字は問わない（コード側で正規化する）。

## 8. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 紙が全く出ない。`last_seen_at` も更新されない | Edge Function がJWT検証で401を返している | `--no-verify-jwt` を付けて再デプロイ |
| 同上 | Server URL のtokenが違う | 管理画面の `device_token` と照合 |
| 同上 | プリンタがHTTPSの証明書を検証できない | ファームウェアを最新に更新する |
| `last_seen_at` は更新されるが紙が出ない | `print_jobs` にジョブが入っていない | `queues.printer_id` が設定されているか確認 |
| 文字化けする | 券面マークアップの文字コード | UTF-8で返していることを確認（Denoの既定はUTF-8） |
| QRが読めない | `cell` が小さい | `cell 6` にする。58mm紙なら `cell 4` |
| 券が2枚出る | `attempts` が2以上 → DELETEが届いていない | ネットワークの安定性を確認。有線LANにする |
| 印刷が10秒以上遅れる | ポーリング間隔が閑散時判定になっている | `pollIntervalMs()` の時間帯設定を営業実態に合わせる |
| Edge Function の呼び出し数が急増 | ポーリング間隔の指示が効いていない | `clientAction` の `PollInterval` が返っているか、Function のログで確認 |

## 9. 印刷なしでも運用できる設計

印刷は**あれば便利だが、なくても業務は回る**設計にしている。

- 発券処理（`issue_ticket`）は、印刷ジョブの投入に失敗しても成功を返す
- キオスク画面には、発券直後に番号とQRコードが**画面上にも**大きく表示される（15秒間）
- ゲストはその場でQRを読み取れば、券がなくてもステータス画面にアクセスできる
- スタッフ画面には印刷失敗が通知され、後から再印刷できる

**導入初期はプリンタなしで「画面表示のみ」で試験運用し、運用が固まってからプリンタを購入する**という進め方も可能。これなら初期費用も0円で始められる。
