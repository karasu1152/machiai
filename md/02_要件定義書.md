# MACHIAI 要件定義書

版数: 1.0 / 作成日: 2026-08-26

## 1. プロジェクト概要

### 1.1 背景と課題

ホテルにおいて、以下2つの場面で待ち行列が発生している。

| 場面 | 発生時間帯 | 現状の課題 |
|---|---|---|
| フロントチェックイン | 15:00〜17:00 | ロビーに列ができ、ゲストがその場から離れられない。混雑がホテルの第一印象を損なう |
| 館内レストラン（朝食ビュッフェ） | 7:00〜9:30 | 待ち人数が把握できず、ゲストが何度もレストラン入口まで様子を見に来る |

いずれも「**待っている間、その場に拘束される**」ことが本質的な不満につながっている。

### 1.2 目的

1. ゲストが**列に並ばずに**待てるようにする（客室・ラウンジで待機可能に）
2. スタッフが**呼び出しに集中できる**ようにし、「次は誰か」の確認コストをゼロにする
3. 待ち時間の実績データを蓄積し、**人員配置の根拠**を得る
4. 上記を**月額0円**で実現する

### 1.3 スコープ

**対象に含む**
- 番号発券（キオスク端末 / スタッフによる代理発券）
- サーマルロール紙への自動印刷
- 待ち行列の管理・呼び出し操作
- 館内サイネージへの呼出番号表示・音声呼び上げ
- QRコード経由のゲスト向けステータス画面
- キュー（待ち行列）の設定管理
- 待ち時間・混雑状況の統計

**対象に含まない（本フェーズ）**
- 宿泊予約システム（PMS）との連携
- 会計・決済機能
- 座席管理・テーブル割り当ての自動最適化
- SMS / LINE / メールによる呼び出し（コスト要件により不採用）
- ネイティブアプリの提供

## 2. 利用者と利用環境

### 2.1 アクター定義

| アクター | 説明 | 使用端末 | 認証 |
|---|---|---|---|
| **ゲスト（発券）** | 待ち番号を取得する宿泊客・来館者 | 館内設置のiPad（キオスク） | 不要 |
| **ゲスト（確認）** | 券のQRから順番を確認する | 自身のスマートフォン | 不要（推測不可能トークン） |
| **スタッフ** | 呼び出し・完了操作を行う従業員 | iPad | メール+パスワード |
| **管理者** | キュー設定・プリンタ設定・統計閲覧 | iPad / PC | メール+パスワード（admin権限） |
| **サイネージ** | 呼出番号を表示する専用端末 | iPad / TV（HDMI接続PC） | 表示専用URL |
| **プリンタ** | 券を印刷する機器 | Star mC-Print3 | デバイストークン |

### 2.2 端末要件

| 用途 | 要件 |
|---|---|
| 発券キオスク | iPad（第7世代以降推奨） / iPadOS 17以上 / Safari / **常時電源接続** / 固定スタンド |
| スタッフ端末 | iPad または PC / モダンブラウザ |
| サイネージ | iPad または PC + 外部ディスプレイ / 横向き固定 / **音声出力可能なこと** |
| ゲスト端末 | iOS 16.4以上 / Android 8以上 の標準ブラウザ |

### 2.3 ネットワーク要件

- 館内Wi-Fi（スタッフ用SSID、ゲストWi-Fiとは分離推奨）
- プリンタは**有線LAN接続を強く推奨**（Wi-Fiは印刷遅延・切断の原因になりやすい）
- 上り下り各 5Mbps 程度あれば十分

## 4. 非機能要件

### 4.1 性能

| ID | 項目 | 目標値 |
|---|---|---|
| NFR-101 | 発券ボタン押下から画面に番号が出るまで | 1.5秒以内（95パーセンタイル） |
| NFR-102 | 発券から紙が排出されるまで | 10秒以内 |
| NFR-103 | 呼出操作からサイネージ・ゲスト画面への反映 | 1秒以内 |
| NFR-104 | 同時待機組数 | 1キューあたり200組まで正常動作 |
| NFR-105 | 同時Realtime接続 | 150接続まで（無料枠上限200に対する安全マージン） |
| NFR-106 | キオスク画面の初回表示 | 3秒以内 |

### 4.2 可用性・信頼性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-201 | 稼働率 | 営業時間中 99.5% 以上（Supabase / Cloudflare のSLAに準拠） |
| NFR-202 | ネットワーク断時の挙動 | キオスクは「一時的に発券できません。スタッフにお声がけください」と表示。スタッフ画面には赤帯で警告。**復旧時に自動で再接続する** |
| NFR-203 | 縮退運転 | ネット断が10分以上続く場合の運用手順（手書き整理券への切替）を運用マニュアルに定める |
| NFR-204 | データバックアップ | GitHub Actions により毎日03:00に `pg_dump` を取得し、プライベートリポジトリに保存する。30日分を保持 |
| NFR-205 | 印刷ジョブの再送 | プリンタが取得しなかったジョブは60秒でタイムアウトし、スタッフ画面に通知。手動再印刷が可能 |
| NFR-206 | 端末クラッシュからの復帰 | サイネージ・キオスクは30秒ごとにヘルスチェックし、異常時に自動リロードする |

### 4.3 セキュリティ

| ID | 項目 | 要件 |
|---|---|---|
| NFR-301 | 通信の暗号化 | 全通信をHTTPS/WSSで行う |
| NFR-302 | ゲストのデータ分離 | ゲストは他人のチケット情報を一切参照できない。DBのRLSで強制する |
| NFR-303 | 匿名アクセスの制限 | 匿名キーではテーブルへの直接書き込みを禁止し、`SECURITY DEFINER` のRPC経由のみを許可する |
| NFR-304 | QRトークン | 128bit相当（22文字のURL-safe乱数）とし、総当たりを実質不可能にする。有効期限は発行から24時間 |
| NFR-305 | プリンタ認証 | CloudPRNTエンドポイントはデバイストークンとMACアドレスの両方で照合する |
| NFR-306 | スタッフ認証 | メール+パスワード。セッション有効期限は12時間（1シフト分） |
| NFR-307 | 個人情報の最小化 | 氏名・電話番号・メールアドレスは**収集しない**。部屋番号のみ任意で扱い、90日後に自動削除する |
| NFR-308 | 監査ログ | チケットの全状態変更を、実行者・時刻とともに記録する |

### 4.4 ユーザビリティ

| ID | 項目 | 要件 |
|---|---|---|
| NFR-401 | キオスクのタップ数 | 発券完了までの操作を**最大3タップ**とする |
| NFR-402 | タッチターゲット | キオスクの主要ボタンは最小 88×88pt（Appleの推奨44ptの2倍。高齢者・手荷物を持った状態を想定） |
| NFR-403 | コントラスト比 | 本文4.5:1以上、大きな文字3:1以上（WCAG AA準拠） |
| NFR-404 | 誤操作防止 | 「取消」「削除」など不可逆な操作には確認ダイアログを出す |
| NFR-405 | 多言語 | 日本語・英語・簡体中国語・韓国語。すべての画面で完全対応 |
| NFR-406 | 学習コスト | スタッフが5分の説明で通常業務を行えること |
| NFR-407 | 片手操作 | スタッフ画面の主要操作をiPad片手持ちで届く範囲に配置する |

### 4.5 保守性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-501 | 技術スタック | React + TypeScript + Vite + Tailwind CSS + Supabase JS。特殊なフレームワークを使わない |
| NFR-502 | 設定の外部化 | ホテル名・文言・キュー定義をコードではなくDBに持ち、非エンジニアが変更できる |
| NFR-503 | ログ | Edge Function のエラーは Supabase のログに残る。印刷失敗は `print_jobs` テーブルに理由が残る |
| NFR-504 | デプロイ | GitHubへのpushでCloudflare Pagesが自動デプロイする |
| NFR-505 | 環境分離 | 本番とステージングでSupabaseプロジェクトを分ける（無料プランは2プロジェクトまで作成可能） |

## 5. 制約条件

| ID | 制約 | 影響と対応 |
|---|---|---|
| CON-01 | **月額費用は0円**とする | Vercel Hobbyは商用利用禁止のためCloudflare Pagesを採用。SMS/LINE通知は不採用 |
| CON-02 | **iOSのWeb Pushはホーム画面追加が必須** | 通知に依存しない設計とする（画面リアルタイム更新＋サイネージ＋音声呼び上げを主とする） |
| CON-03 | **Supabase無料枠のEdge Function呼び出しは月50万回** | プリンタのポーリング間隔を営業時間中10秒・時間外停止に設定する |
| CON-04 | **Supabase無料枠は7日間無アクセスで自動停止** | ホテルは毎日稼働するため実害なし。長期休業時のみ対応 |
| CON-05 | **Supabase無料枠は自動バックアップなし** | GitHub Actionsによる日次 `pg_dump` で代替 |
| CON-06 | **HTTPSページからLAN内HTTPプリンタへの直接印刷は不可**（Mixed Content） | プリンタ側からサーバーをポーリングするCloudPRNT方式を採用 |
| CON-07 | **プリンタはCloudPRNT対応機種に限る** | `MCP31CBI` / `MCP31CI` を指定。`MCP31LB` / `MCP31L` は不可 |
| CON-08 | **iPadのSafariはネイティブの自動印刷ができない** | 上記CloudPRNT方式により、iPad側は印刷に一切関与しない設計とする |

## 6. 受け入れ条件（Acceptance Criteria）

以下がすべて満たされたとき、システムを本番稼働可能と判断する。

### 6.1 発券

- [ ] キオスクで「チェックイン」を選び、人数を選び、発券ボタンを押すと、**3タップ以内**で発券が完了する
- [ ] 発券から**10秒以内**にロール紙が排出される
- [ ] 券面の番号が視認でき、QRコードがiPhone・Androidの標準カメラで読み取れる
- [ ] 発券ボタンを連打しても、券は1枚しか出ない
- [ ] 受付停止中のキューは、キオスクで選択できない

### 6.2 呼び出し

- [ ] スタッフが「次を呼ぶ」を押すと、**1秒以内**にサイネージへ番号が表示される
- [ ] サイネージでチャイムが鳴り、日本語と英語で番号が読み上げられる
- [ ] ゲストのスマホ画面が同時に赤く点滅し、音が鳴る
- [ ] 「不在」にしたチケットを、待機列の先頭または最後尾に戻せる
- [ ] 2台のスタッフ端末で同時に「次を呼ぶ」を押しても、**同じ番号が二重に呼ばれない**

### 6.3 ゲスト画面

- [ ] QRを読み込むと、認証なしで自分の順位が表示される
- [ ] 前の組が呼ばれると、操作なしで「あと N組」が減る
- [ ] 他人のトークンを推測してアクセスすることが実質不可能である（22文字のランダム）
- [ ] 4言語すべてで表示崩れがない

### 6.4 障害時

- [ ] Wi-Fiを切断すると、キオスクが「発券できません」と表示する
- [ ] Wi-Fiを復旧すると、リロードなしで発券可能に戻る
- [ ] プリンタの電源を切って発券すると、画面には番号が出て、スタッフ画面に印刷失敗が通知される
- [ ] プリンタの用紙を抜くと、スタッフ画面に「用紙切れ」が警告表示される

### 6.5 性能

- [ ] 200組のダミーデータを投入した状態で、スタッフ画面の一覧が2秒以内に描画される
- [ ] ゲスト端末50台から同時にステータス画面を開いても、全端末で順位が正しく更新される

### 6.6 コスト

- [ ] 1か月稼働させた後、Supabase / Cloudflare の請求額が **0円** である
- [ ] Supabaseダッシュボードで、Edge Function呼び出し数が月間上限の70%未満である

## 7. 用語定義

| 用語 | 定義 |
|---|---|
| **キュー（Queue）** | 独立した待ち行列の単位。「フロントチェックイン」「朝食レストラン」など |
| **チケット** | 1組のゲストに対して発行される待ち番号のレコード |
| **表示番号** | ゲストに見せる番号文字列。`プレフィックス + 3桁連番`（例：`C-012`） |
| **窓口（Counter）** | 実際に案内を行う場所。「1番カウンター」「レストラン入口」など |
| **呼出中** | スタッフが呼び出したが、まだゲストが到着していない状態 |
| **案内中** | ゲストが到着し、対応・着席が始まった状態 |
| **不在** | 呼び出したがゲストが現れず、いったん列から外した状態 |
| **業務日** | 統計の集計単位。既定は 04:00 から翌03:59 まで（深夜営業を1日として扱うため） |
| **CloudPRNT** | Star Micronics のプロトコル。プリンタがサーバーへHTTPポーリングして印刷ジョブを取得する |
| **RLS** | Row Level Security。PostgreSQLの行単位アクセス制御 |
